## Бригадир

Исходники маркетплейса ремонтных бригад для Казахстана.

Сайт: https://brigadir-kz.alizhansamat087.chatgpt.site/

### Возможности

- Каталог бригад с поиском, городами, категориями, сортировкой и ценой за м².
- Профили компаний и портфолио выполненных проектов.
- Личный кабинет: создание и редактирование своего профиля, загрузка фотографий.
- Серверное сохранение в Cloudflare D1; изображения в R2.
- Мобильная верстка, анимации с поддержкой reduced motion, SEO-метаданные, robots.txt и sitemap.xml.
- Серверная авторизация, проверка владельца, валидация входных данных, лимиты загрузок/запросов и CSP с nonce.

Демонстрационные профили, цены и рейтинги обозначены как примеры. Подтверждённые отзывы и оплата ремонта пока не реализованы.

### Запуск локально

Требуется Node.js >=22.13.0 и npm.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_fine_jack_murdock.sql
npm run dev
```

Разработка: http://127.0.0.1:5173/. Локальная имитация входа включена только для разработки на loopback. Для входа в кабинет откройте `/signin-with-chatgpt?return_to=/cabinet`.

```sh
npm run build
npm start
```

`npm start` запускает локальную собранную версию Worker и не публикует сайт. В ней нет локальной имитации входа.

### Структура

- `app/` — страницы, интерфейс и API.
- `lib/` — данные каталога, доступ к базе и проверки безопасности.
- `db/schema.ts`, `drizzle/` — схема и миграция базы.
- `build/sites-worker.ts` — вход Worker и защитные HTTP-заголовки.
- `public/images/` — лицензированные демонстрационные фотографии.
- `.openai/hosting.json` — идентификатор существующего сайта и логические привязки DB/BUCKET; секретов в нём нет.

### Развёртывание и безопасность

Эта версия настроена на Sites и доверяет идентификации пользователя, которую передаёт шлюз платформы. При переносе на другой публичный хостинг необходимо заменить авторизацию; напрямую доверять клиентским заголовкам пользователя нельзя.

Для собственного домена обновите разрешённый origin в `lib/security.ts` и SEO-адреса. Публикация кода на GitHub не меняет доступ к уже работающему сайту.

Реальные пользовательские данные, фото из R2, локальная база, зависимости, временные файлы и секреты не включены в репозиторий.

Подробнее: [границы безопасности](SECURITY.md), [права на фотографии](ASSET-CREDITS.md), [инструкция исходного шаблона](docs/SITES-STARTER.md).
